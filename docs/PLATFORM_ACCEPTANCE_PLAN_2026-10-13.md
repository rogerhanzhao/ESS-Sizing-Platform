## 目标和范围

以实际使用者视角检查全部公开页面、可见控件及业务流程：打开、选择、输入、提交、保存、恢复、生成、上传、下载、失败后重试。检查页面操作是否可理解，数据是否一致，附件是否适合客户和投标使用。

涉及域：Web UI 与会话状态、产品及数据库管理、DC/AC 计算结果的展示与持久化、SLD、布局及约束、报告、平台连接与日志。按页面读取对应包，不扫描全库。

既定计算逻辑保持冻结。检查计算结果与已持久化结果、既有基准是否一致，不重新定义公式、阈值、SOH/RTE 或方案语义。新衰减版本继续作为候选参考，不在检查中激活。

## 环境与操作边界

- 线上：已授权账号进行页面浏览、筛选、历史恢复和下载检查；保留现有真实项目。
- 写入流程：优先在生产数据库的本地副本运行真实应用，以 `QA_20261013_` 前缀建立测试项目、算例和版本。副本使用独立数据库、输出目录和端口，不连接生产写入。
- 清库、账号角色变更、禁用账号、有效 SOH/RTE 迁移、批量覆盖和插件状态修改只在隔离副本测试。线上不执行这些动作。
- 线上需要生成测试 run 或附件时，使用明确标记的测试项目，先记录操作范围；权限不足、缺少账号或数据时记录阻塞，不冒充通过。
- 管理员、普通登录用户、Guest 分别检查。登录及身份验证由用户完成；没有对应会话时，权限自动测试与人工页面检查分开记录。
- 服务器巡检与部署遵循 `docs/ops-local/DAILY_OPS_LOOP_V1.md`；不触碰 EnerGain。
- 浏览器安全阻断不自动绕过。目前 HTTP 下载拦截单独列为环境问题；生成成功不等于下载成功，下载成功不等于附件打开成功。

## 所有页面统一检查

1. 观感：1366×768、1920×1080，浏览器 100% 及当前 90% 缩放；首屏重点、滚动长度、表格宽度、图例、折叠区、文字密度和按钮层级。笔记本为主要验收设备，手机为补充。
2. 数值：单位、百分比、精度、零值、空值、N/A、负值、边界值，避免内部长 ID 和服务器路径出现在客户附件中；详情诊断可保留必要标识。
3. 交互：默认值、必填项、禁用原因、提交反馈、耗时提示、重复点击、切页返回、刷新、浏览器重新打开和 VPN 重连。
4. 状态：更换项目、算例、DC run、AC alternative 后，设置、结果、SLD、布局及报告不串用；上游改变后的旧结果明确标识或失效。
5. 异常：缺项、非法字符、超长输入、格式错误、文件超限、重复上传、缺失关联、附件不可读；显示可操作的提示而不是 traceback。
6. 权限：隐藏入口不足以证明权限；通过隔离环境的服务端测试验证权限检查。角色变化与旧会话也纳入测试。
7. 性能：记录冷/热加载、保存、计算、图件生成、导出耗时。普通导航超过 3 秒、保存超过 5 秒进入复核；长任务不统一以秒数判失败，但必须有状态反馈且不重复执行。失败按实际环境区分网络和应用。

## 跨页面业务用例

| 编号 | 路径 / 场景 | 检查重点 |
|---|---|---|
| E01 | 新建项目→算例→DC→AC→SLD→布局→报告→历史恢复 | 标准主链完整；数量/功率/能量及附件来源一致 |
| E02 | 两个项目、同名算例交替切换 | project/case/run 隔离，旧附件不混入新方案 |
| E03 | 恢复历史 DC run→选择 AC A/B→分别出图与报告 | 每个 alternative 的参数、名称和来源完整一致 |
| E04 | Guest 计算→尝试持久化/导出→普通用户→管理员 | 权限与页面提示一致；无越权写入 |
| E05 | 修改上游输入/工程设置后返回下游 | 失效行为、待确认状态及重新生成入口合理 |
| E06 | 缺产品数据、未确认向量组、资料读取失败 | 不虚构工程值；非正式原因及读取重试明确 |
| E07 | 1:8 分组、均匀站、混合头尾方案；两/三绕组 | 使用既有规则及基准；典型方案与全站结果分别披露 |
| E08 | 浏览器刷新/重新登录、网络断开后恢复、多标签页 | 保存数据仍可读取；会话状态变化明确；无重复写入 |
| E09 | 导入正常文件→重复文件→错误文件→刷新→导出 | 回读与幂等性；错误不部分落库；导出可追溯 |

计算比较使用现有标准算例与快照，不自行推导新的 sizing 规则。每个可见 scenario 至少覆盖一条正常主链；边界及混合方案在副本补充。

## 附件单独验收

- 登记每一个 download 按钮：页面、格式、所用项目/算例/方案、下载文件名、实际保存路径、文件大小、生成/下载/打开状态。
- Excel：本机打开无修复提示；百分比是真实数值且显示两位小数；图表有数据、图例清楚、缺值不补造；冻结、列宽、目录、打印页和分组合理。管理区原有模板/CSV 要逐项审查，确定哪些应增设格式化 Excel，不直接破坏机器导入模板。
- DOCX：本机打开、标题及页眉页脚、表格跨页、图片比例、单位、品牌及来源；报告内概念工程图保留 NOT FOR CONSTRUCTION。
- PDF：仅对实际提供的 PDF 出口验收，核对文本、页数和渲染，不把当前没有的 PDF 功能记为通过。
- SVG/PNG：放大后线条、符号、连线、文字不重叠；可读性与水印；预览和下载一致。
- JSON/图纸包：可解析、包含预期文件、来源一致，技术文件与客户呈现文件分开评价。

状态仅使用：未测 / 通过 / 失败 / 阻塞 / 不适用。不适用必须写理由。自动测试、真实浏览器和本机附件打开分别标记，不能相互替代。

优先级：P0 数据丢失/越权/错误串方案；P1 主流程、保存、出图、下载不可用或结果误导；P2 易误操作、版式不清、提示不合理；P3 一般观感及效率改进。

先提交检查发现，再按原有授权处理常规 bug 与小幅 UI 优化。涉及冻结逻辑、新子系统、新闸门、权限或部署架构的变更单列决策项。修复后只复测受影响流程；提交前 compileall、完整 pytest、冻结与报告边界检查，UI 改动运行真实应用；上线遵循 GitHub→备份→CALB 部署→健康验证→浏览器复测。

结束条件：所有已登记操作均有状态；正常主链完成；P0/P1 修复并复测或明确列出阻塞；每一种实际下载格式完成生成、下载和打开检查；保留 P2/P3 待办；提交最终覆盖清单与未解决项，不宣称“全部通过”来掩盖缺失账号或环境限制。
