## 1. 已核实的问题

1. `ProductAdminService.df_blocks_as_sizing_dataframe` 仅输出产品代码、名称、形态、容量、启用、默认六列。电芯外键、电压、电流、连续功率、版本与曲线关联没有进入这一适配接口。
2. `stage2_service.pick_dc_block` 每种形态只取一款；原有记录启用是候选条件，发布标记被映射为默认偏好，其后按容量降序。未发布的启用产品在没有默认项时仍可被选中。发布不是工程批准，也不是枚举所有规格。C2a新增工程子配置由适配层独立隔离，不进入该标准选择器。
3. `dc_pipeline_service` 的 container/cabinet/hybrid 仅消费一个 container 和一个 cabinet；原 hybrid 不表示多种 container 任意混搭。不能仅改勾选框就声称支持 12+10+8 簇组合。
4. `Stage2ConfigItem` 虽可存多行，但缺少每件设备与独立电气组的身份、参数版本及连接分配。总量、形态相同不证明后续 AC 接口支持异构设备。
5. 柜式报告入口明确要求 cabinet_only；混合 AC 的代表性 head-fleet SLD 不能变成全站逐台图的证据。
6. 本地 `var/calb_sizing.sqlite` 只读核查发现：418kWh 条目被标为 container；5MWh 与418条目关联不同 cell 外键；588/661Ah 条目均启用且发布，存在连续功率/电流为0、曲线未关联等情况。当前 picker 可能选择容量最大的661Ah条目。这只是该本地库的实测，不能当作线上库或当前8511服务的同一状态。原始审计保存在 output/flexible_dc_local_20261020/local-product-audit.json，未修改记录。

## 2. 目标与不变项

保留 5MWh 标准路线及其默认结果、逐页流程和直接下载技术方案。冻结 Stage1 效率链、保证年迭代、SOH/RTE、K_MAX_FIXED、现有 AC 阈值与原始 SLD 引擎。本轮先实现诊断和明确的新接口；任意多规格组合涉及受控搜索语义扩展，须先形成具体测试及兼容契约，再记录 canon 修订，不能在 UI 或报告里暗改公式。

同一款电芯是候选族的必要条件之一，不是并联许可。相同314Ah不等于相同型号/修订/电压窗口/性能依据。同族但电芯外键重复的历史数据要有证据合并映射，不能按容量字符串自动合并。更大电芯独立成族；默认禁止跨族混合。

## 3. 产品数据库与维护

沿用 product_cell、product_dc_block、曲线和附件主表。12/10/8簇作为独立、可修订的产品配置，不从名称推导簇数，也不自动按12簇容量比例伪造其他规格。每款维护：产品代码/修订、父产品族、准确电芯型号/修订、串并结构、簇数、额定能量、DC电压范围、充放电连续功率/电流限制及温度条件、独立输出回路、外形/质量、适用图纸模板、产品资料来源。

现有字段优先复用；缺少的关系（性能证据适用、发布审核、输出端口、参数快照）在阶段B确定正式 schema/迁移，不把长期合同塞进随意JSON。禁止在未验证支持前直接修改现有 Active/Published 的语义。

计划增加独立的 sizing_release 状态：Draft → Parameter review → Candidate-only → Released for sizing → Retired。发布审查验证所需关联和参数，并记录谁、何时、何证据、何修订；Active控制生命周期，Published控制目录可见性，Release控制新搜索资格。旧选择器在新开关关闭时保持原义，不能静默改变旧记录行为。

资料和退化曲线分别管理：目录链接、运行时profile映射、工况覆盖范围、有效年限、产品适用证据须分开检查。314Ah曲线不能默认分配给588/661Ah。完整参数也不自动构成质保或安装合规批准。

## 4. DC 搜索与比较

前台先选择产品族，再选 Standard / Extended configuration（英文界面）。Standard保持现有5MWh路径。Extended只在明确选择后开放已获准的12/10/8簇和尾柜候选，不把少用规格全部挤进默认页面。

实施次序：先做同族单一规格的候选比较，每个候选通过受控输入数据独立调用现有管线，重用其保证年结果；再做12簇主箱+一种尾箱；最后才扩展多种尾箱和尾柜的组合搜索。后两者不能冒用原 hybrid 的结果语义，需要专用候选清单与受控的Stage2组合入口，仍消费同一Stage1/Stage3定义。

候选记录完整BOM：产品代码+修订+数量+单位能量；每候选保存独立输入/输出及可复现签名。先可行性（保证年POI能量、功率/电流/电压），后呈现过配、箱数、独立组数、AC容量、尾组利用率。没有价格数据不得称为最低成本。限制候选数量和有依据的尾箱种类，避免无穷组合。任何年限/工况无数据明确阻断，不自动外推。

## 5. AC 功率匹配与统一设备分配

新增独立的版本化 station allocation contract，而不是把异构箱数平均摊入旧ratio。链路为：设备实例 → 独立DC组 → PCS输入端口/PCS → 变压器绕组 → AC Block → MV馈线。保留每条连接的产品/版本/数量和电气界限。

每组检查PCS输入窗口、每端口与总输入电流、充/放电连续功率、DC组功率、PCS输出、变压器MVA/PQ/绕组与POI效率链。短组不能以全站总功率掩盖局部不足；不能把不同独立组画成并联。尾柜独立成组，沿用已确认最多12柜的AC组接口；原DC混合搜索K_MAX_FIXED=10是不同含义，不改成12。

可推荐多个PCS/AC Block方案，但仅自动填有证据的参数；缺少端口/产品限制时展示待核实，不能报已可行。现有手动混合AC和纯5MWh入口保留。每候选至少逐组闭合及全站POI闭合，采用现有阈值，不新设隐含放宽值。

## 6. SLD、Layout、报告共同消费

三者均消费同一持久化allocation签名，不在渲染层重新分组或推测数量。

- SLD：保留原5MWh引擎；新增异构适配/图纸包，明确典型图范围，头组和尾组分别出图，附全站组别设备表，不能用一张头组图冒充全部组。
- Layout：产品真实外形、设备实例/端口朝向、独立组边界由快照驱动；缺少安装资料时保持concept及待确认标记。8/10簇若共享20ft外形也须产品依据。安装距离不得从热失控测试摆放直接当作通用最小距离。
- 技术方案：保留九章和原下载流程；新增DC配置BOM与AC组合/逐组分配表，清楚列出主箱、10/8簇尾箱、尾柜分别供给哪个PCS/AC组。正文只显示人可读方案/设备编号，数据库UUID留后台。
- 产品修改不回写历史方案；历史run依靠版本快照复现。若拓扑或BOM签名改变，旧图和报告失效待重生成，不能继续显示为当前匹配。
