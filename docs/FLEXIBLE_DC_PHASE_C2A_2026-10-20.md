# C2a：5MWh 20ft 主箱与8/10簇子配置

本轮主线固定为现有314Ah、416S、12簇20ft集装箱，加8簇、10簇两种特殊配置；更大电芯产品资料继续归档，但不替代此主线。这里的簇数指 `strings_in_parallel`，不等于物理rack数量、输出回路数量或PCS数量。

状态：本地母子配置关系、显式BOM、数据库隔离演练与管理员面板已实现；混合DC求解、AC逐组匹配、SLD/Layout/技术方案采用仍在后续阶段。原5MWh sizing公式和图纸引擎未改动，没有提交、推送或生产升级。

## 1. 这两个子配置解决什么问题

12簇作为主箱优先。只有特殊工程需求才比较“若干12簇主箱 + 一种8/10簇尾箱”；首个搜索版本限制为一种尾箱规格、最多一台尾箱，后续再评估多种尾箱、尾柜，不把原来container/cabinet/hybrid语义扩成任意混搭。

主要价值是减少整箱向上取整形成的剩余装机容量，或满足特定PCS支路/独立DC域的配置要求。8/10簇若仍用同样20ft外壳，箱数、占地不一定减少；没有材料/价格数据时不宣称最低成本。变少的并联簇数也可能降低允许电流及功率，不能只看节省的MWh。

名义能量工程算例：314Ah × 3.2V × 416S × 簇数。8簇为3.3439744MWh；10簇为4.179968MWh。这是电芯参数计算值，不是已发布子产品额定值，不代表可用DC能量或保证年POI能量。实际运行前必须以该子配置获准的参数修订为准。

隔离演练保留原目录母产品5.015960MWh，没有为了算式整齐而改写原产品：

| 仅用于检查BOM的组合 | 箱数 | DC能量合计（MWh） | 说明 |
|---|---:|---:|---|
| 3 × 12簇 | 3 | 15.047880 | 原目录标准单机容量 |
| 2 × 12簇 + 1 × 10簇 | 3 | 14.211888 | 尾箱能量为工程计算值 |
| 2 × 12簇 + 1 × 8簇 | 3 | 13.375894 | 尾箱能量为工程计算值 |

上表没有输入项目需求、寿命、DoD或效率，不能据此选择最终方案，也不能作为客户性能承诺。

## 2. 数据库中的使用逻辑

1. 12/10/8簇是独立 `ProductDCBlock`，各自维护电芯外键、串并结构、额定能量、持续功率/电流、电压、外形及证据。共享电芯不表示自动共享曲线批准。
2. 参数修改后捕获独立 `DcCatalogueRevision`，原历史快照不回写。产品、电芯或关联曲线修改后，旧审核失效；把数值改回去也不会恢复旧审核。
3. 新表 `dc_configuration_variant` 将一个12簇母产品修订关联到一个8/10簇子产品修订，保存双方哈希、族代码、版本、依据和审核事件。必须同一准确电芯、416S、同电压范围、明确20ft外形，不能按同为314Ah或外观猜关系。
4. 关系默认为 `special_scenario_only`，状态只有Draft / Candidate only / Retired；没有正式运行发布状态。双方参数审核、配置关系审核、性能工况适用是不同检查。
5. 新标记的工程子配置和所有已登记子产品，在旧六列适配器中输出 `Is_Active=0`。即使目录Active/Published被勾选、marker被删除或子产品新增修订，也不能偷偷进入旧picker；其他原有记录的语义保持不变。
6. C1单规格比较通过独立数据适配调用原管线。子配置必须有当前有效的母子关系、明确特殊场景开关及原因；计算前后复核关系与修订。仍不保存、采用或激活正式run。

本地脚本 `scripts/rehearse_dc_container_variants.py` 只允许目标为仓库output下不存在的新文件，以只读SQLite backup复制源库再迁移。在副本中创建Inactive / Unpublished工程草稿；功率、电流、曲线、输出分区及rack构造不从母产品比例推导。继承外形/电压标为设计假设。源库和生产库不迁移。

## 3. 一份BOM贯穿后续的基础

`dc_composition_manifest_service`消费明确的产品修订、正整数数量、主箱/尾箱角色；不执行搜索，不把多种箱体平均成一个虚构产品。

- 保留每行产品/修订/哈希/数量/单机与小计能量、来源及工程假设。
- 展开DC-001、DC-002等物理设备，逐件保留配置；拒绝重复产品修订、错族、过期修订、反向角色和模糊数量。
- 输出域需要明确的簇数、能量、功率、电流及证据。逐箱分区簇数与能量必须完整，不从8/10/12簇猜“一路/两路”。缺少时域列表为空且AC保持待定。
- 额定值的presence检查只说明字段存在，不说明整箱总限制、各端口限制、PCS、电压窗口和POI功率已闭合。`electrical_limits_reconciled=False`明确保留下一阶段工作。
- 完整清单有内容签名。此阶段恒为 `comparison_only=True`、`downstream_ready=False`；不能送入旧AC平均分配后宣称可行，也不产生新SLD、布局或客户技术方案。
- 本地展开10,000台上限仅是内存保护，不是项目箱数或sizing业务规则。

## 4. AC及后续阶段的具体落地顺序

| 下一步 | 实施要求 | 必须通过的验证 |
|---|---|---|
| C2b：受控混合DC候选 | 保留原标准入口；专用组合入口优先12簇，比较一个10簇或8簇尾箱。先记录受控canon扩展再实施，不在UI里私算保证年 | 同一Stage1/Stage3定义；按各配置实际工况查证性能，避免用全站平均C-rate掩盖尾箱超负荷；标准12簇基线逐项等价 |
| D：逐组AC候选 | 从物理箱→独立DC域→PCS端口/PCS→变压器绕组→AC Block逐件映射。保留用户已有手动混合AC流程 | 每域及整箱持续功率/电流、DC电压、PCS、变压器及POI同时闭合；最小尾组不能由头组余量掩盖；跨独立域不误并联 |
| E1：图纸适配 | 原5MWh SLD引擎沿用原路；新异构图包按头/尾组分别出典型图及全站配置表 | 同一物理箱的独立输出不得跨AC Block；不同PCS不得共用同一DC母线；图与实际分配逐项一致 |
| E2：布局、报告 | 原九章、连续页面流转和直接下载保留。展示主箱/尾箱BOM与逐AC组组合表 | 外形/安装依据适用；全部图纸逐页复核；人类编号进正文，数据库UUID留后台 |
| F：本地Web贯通 | 新候选采用前完整验证跨页、历史恢复、重算、图纸、直接导出 | composition与allocation签名必须进入AC身份和图纸/报告失效检查，防止相同箱数下12簇换8簇仍复用旧图 |

当前 `ac_run_service._IDENTITY_FIELDS` 尚无新清单签名，旧AC电气结构只支持既有输出回路假设。正式采用前必须扩展受控接口并回归；C2a不会绕过这两点。8/10簇采用同外壳、同电压仅是本地设计假设，厂家正式参数、输出分区和性能适用证据需逐项补齐，而不阻止本地接口和异常测试继续进行。

## 5. 本地入口与验证

原产品管理页新增默认关闭的 `CALB_DC_VARIANT_REVIEW=1` 管理员面板；现有修订和C1开关保持各自独立。新面板支持母子关系登记/审核、明确数量BOM、逐箱台账和审核JSON导出。正文表格不展示数据库UUID；JSON保留追溯信息。

同一会话下载或普通rerun保留最后复核的BOM预览；产品/关系审核改变时使预览失效。完整浏览器刷新建立新会话时可重新选取已入库关系并复核，不宣称跨会话保存了一个正式sizing结果。

隔离库与实测记录：`output/flexible_dc_phase_c2a_20261020/`。测试数据与工程草稿不是CALB发布产品数据。

最终复验：专项226项通过（94.80秒），最终全量1272项通过（362.62秒）；前一轮全量1266项通过后，又完成独立审查修复和最终全量验证。编译、diff检查、七个冻结模块与calb_diagrams差异为空的检查通过。

真实浏览器在独立8523端口检查了：缺少特殊场景选择时阻止提交；2×12+1×8与2×12+1×10分别显示13.375894/14.211888MWh；两种关系输入不混用；逐箱DC-001/DC-002/DC-003台账；点击JSON下载后预览保留。AppTest另外验证普通rerun预览保留、目录变更失效、非管理员不能读库、588Ah候选不出现在此314Ah子配置选单、缺参不可批准。浏览器页面是隔离工程面板，不是正式签入系统全链路验收。

数据库核对：源库版本仍为0010，副本升级到0012；32张原有表的源记录全部保留，完整性检查ok。源本地诊断库已有16条角色/附件历史孤立外键，副本中完全相同，本次新增外键错误为0。它们需后续按历史用户/run来源核对，未自动删除或伪造关联，也不能据此推断生产库存在相同问题。详见 `source-preservation.json`。
