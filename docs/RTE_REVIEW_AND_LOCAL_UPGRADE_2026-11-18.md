## 3. 当前可以可靠执行的计算方案

1. 新SOH轨迹决定各年的容量保有率H；不按旧年序列复制效率。
2. 0.25C/0.33C采用已审核基础输入，0.5C按已复核的1.6差值关系生成；生成结果作为可审核的RTE输入表。
3. 沿用原Stage3按倍率选RTE profile、按当年H选SOH区间的规则。原`rte_monotonic_enforce`、`rte_curve_adjust_pp`及DC到POI效率链继续生效；不改变其公式或顺序。
4. 因此不同SOC/循环工况的SOH下降时间不同，会在不同年份进入同一效率区间；不需要给160条SOH各造一套没有证据的独立效率公式。
5. 用户指出新供应商公式后，先验证该公式与旧规则在BOL、中间SOH、60%及更低SOH边界的差异，再决定是否替换生成方法。该步骤尚未完成，当前不宣称“已按新供应商公式计算”。

### 低SOH边界必须明示

旧表最后明确标注的SOH下限为60%，另有两行未标SOH区间的RTE数值。历史导入将这些空阈值转换成0，原引擎可能在低SOH使用这些回退行。当前保持该历史查表行为以维护原计算逻辑，但不将其描述为新增的0–60%测试数据。

管理预览逐年标出`legacy_low_soh_fallback`；新Run的依据记录保存是否使用该回退，技术报告亦说明实际发生的回退。若新供应商公式明确支持更低SOH，应另行审核其适用范围后形成新发布版本，不能从当前空白模板推断。

## 4. 管理员操作接口（已在本地实现）

入口：原“Product & Database → Degradation”页面内的`RTE calculation, editing and publication`。

1. 选择已发布SOH版本作为基础；首次按已复核旧规则准备RTE数据。
2. 查看倍率、SOH下限与DC RTE；只开放RTE百分数编辑，保持曲线与区间结构。
3. 输入新版本名称及修改/适用性说明，点击`Save RTE working draft`。
4. 草稿写入本地数据库，可刷新重开、继续修改；保存使用hash检查，拒绝覆盖他人已更新的草稿。
5. 检查“新SOH → 逐年RTE”匹配预览；预览采用单调约束开启、项目修正0pp，不冒充特定项目的最终POI效率。
6. 点击`Publish saved RTE version`后生成新的不可变运行版本；当前全局默认不会自动改变。
7. 在现有版本管理区域显式设为默认，或在DC页面只为本算例选择该新版本，再重新Run Sizing。

已发布数据不能原位改写。之后继续调整需从该版本创建新草稿；原手动值保留在工作副本里。保存和发布都检查管理员身份、数值有限且在0–100%范围、同区间倍率效率顺序，并保留修改原因与审计。手动值可能受运行时单调约束及项目修正影响，因此须区分“原始输入值”和“最终应用值”。

Run保存完整输入包、RTE版本及生成/手动修改依据；报告读取Run，不读取当前默认设置。修改新默认不会重标旧报告。
