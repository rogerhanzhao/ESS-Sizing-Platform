# 管理员产品数据库：维护与使用流程审查

日期：2026-11-19。范围：当前管理员 Product & Database 页面及其直接数据接口。

本次先统一流程说明和操作名称，保留已有数据、权限、发布接口及选型规则。普通产品的完整版本管理属于后续独立设计，不在此次帮助文案更新中实现。下列行号为审查时的定位，后续文案修改可能使其移动。

## 1. 审查结论

管理员页面应统一回答三个问题：**正在维护什么、保存会改变什么、下一次计算怎样使用它**。共同的说明方式可以统一，实际执行机制须明确区分：

| 对象 | 保存与发布的真实机制 | 当前使用与停用方式 |
| --- | --- | --- |
| 供应商源工作簿 | 保存原文件及全部解析曲线；查看筛选不裁剪保存范围 | 源文件不等于可用于 SIZING 的已发布版本 |
| SOH + RTE 曲线版本 | 保存完整 RTE 草稿；一次发布完整版本；发布内容固定 | 单独选择版本和条件作为默认，或在项目中选择；停用限制后续新计算 |
| Cell、DC Block、AC Block、Asset | 保存时直接修改目录记录；Active / Published 为记录字段 | 消费者对字段的处理不同；尚无统一发布快照、版本回退机制 |
| 目录 Degradation / RTE 记录 | 目录参考信息，沿用可编辑记录模式 | 修改这些记录不修改已发布曲线版本及其默认绑定 |

因此，不将普通产品的 Save Changes 改称“发布版本”，也不将目录中的 Published 一概解释成“允许所有计算使用”。

## 2. 曲线的完整操作路径

入口：**Product & Database → Degradation**。

1. **查看当前使用依据**：顶部 Current sizing default 显示当前版本和 SOC / Mean / Lower limit 条件。
2. **准备数据**：新 SOH 来源在 Source workbooks 保存完整源文件；调整 RTE 在 Revise RTE 选择基础版本并编辑输入。
3. **逐项检查**：年度预览一次显示一个条件、倍率和循环频率，便于人工检查。筛选只改变显示，不改变草稿包含的数据。
4. **保存完整草稿**：可反复保存修改。系统当前没有“每个工况已确认”的持久化记录或必须逐一打开的门禁。
5. **统一发布**：人工完成所需检查后，一次发布完整 SOH + RTE 版本。发布本身不运行 SIZING，也不切换默认。
6. **应用**：在已发布版本管理区选择版本及默认条件，点击应用；特殊项目也可在 DC 页面选择已发布版本，随后点击 Run Sizing。
7. **回退默认**：在同一管理区选择此前仍处于可用状态的版本及条件，再次应用为默认。原已保存结果不被重算；已有明确选择不会被静默改写。
8. **停止新计算使用**：在版本管理区停用指定版本。当前默认版本必须先切换默认后才能停用。历史结果保留；需要用已停用版本重新计算时，现有逻辑要求选择可用版本。

当前没有“重新启用已停用版本”的接口。回退目标须仍为 published；界面不得暗示可随时启用 retired，也不得把停止使用等同删除历史数据。

### 已验证的代码边界

- `ui/supplier_degradation_preview.py:145-156`：保存源工作簿及所有曲线；`164-165`：筛选为查看用途。
- `ui/rte_review_controls.py:128-138`：预览选择独立于保存参数；保存未传入所选 family、rate 或 cycles。
- `services/rte_review_service.py:117-148`：保存完整草稿；`151-183`：完整发布，非 RTE 内容必须与基础版本相同。
- `ui/curve_release_controls.py:70-88`：当前默认只读；`96-159`：已发布版本及显式默认应用；`160-201`：从源文件发布；其后为停用入口。
- `services/curve_release_service.py:157-182`：带修订检查的默认切换；`184-196`：当前默认不得停用；`198-212`：新计算拒绝非 published 版本。
- `ui/curve_release_controls.py:11-62`：项目选择在下一次 Run Sizing 使用，不自动改系统默认或历史结果。

## 3. 普通产品与曲线机制的差异

### Cell / DC / AC / Asset 的共同机制

`ui/admin_portal_view.py:434-437` 将 Active、Published 和字段修改一并保存；`repositories/product_admin_repository.py:134-145` 直接修改原记录。`infra/db/base.py:46-48` 默认 Active=True、Published=False。

这些对象当前没有普通产品版本快照、独立发布动作、删除入口及旧版本回退接口。Source version / version_tag 是来源标记，不构成历史版本存储。保存产品不能笼统解释成“仅保存草稿”。

CSV / Excel 普通导入只新增代码，既有代码不覆盖：`services/product_admin_service.py:235-283`。AC 的预置目录刷新是按代码原地新增或更新：`services/ac_block_product_seed_service.py:72-113`，须单独说明，避免与只新增导入混淆。

### DC Block

- `services/product_admin_service.py:172-210`：Active 映射为标准选型资格；Published 映射为 Is_Default_Option。
- `services/stage2_service.py:13-24`：在 Active 候选中优先选 Published；没有 Published 时仍可选择 Active 候选。
- 工程子型号仍独立限制，不能因打勾而进入标准选型。
- 建议说明：**保存直接更新目录。Active 控制现有标准搜索资格；Published 是现有选型规则中的优先标记。特殊配置继续使用其独立入口。**

### AC Block：需独立处理的现有缺口

`services/ac_block_product_match.py:75-95` 按 PCS 数量、功率和拓扑匹配，没有按 is_active / is_published 过滤。UI 实际调用在 `ui/ac_view.py:1126-1130`，绑定产品参数在 `1592-1593`。

因此当前不能承诺取消 Active 或 Published 就会停止 AC 候选使用。此次说明应明确目录标记与实际匹配之间的关系；修复过滤需先形成单独、有边界的设计和测试，不在帮助文案更新时改变 AC 选型行为。

### Cell 与附件

Cell 的 Active / Published 会影响目录诊断说明（`services/dc_catalogue_readiness_service.py:49-50`）；实际电芯适用性检查核对明确型号与电气基础（`services/dc_product_curve_guard.py:63-83`）。不能承诺停用一个 Cell 就会自动停止所有关联 DC 产品。

Asset 保存文件、产品关联和元数据，支持查看和下载（`ui/admin_portal_view.py:1307-1345,1378-1427`）。新保存附件是否出现在报告取决于具体导出模板；不能描述为“保存或发布即自动加入所有报告”。

## 4. 本次页面说明设计

后台保持现有导航。各页共用顶部可折叠的简短维护说明，各相关页面就地说明保存及使用后果；不重复长篇说明。

统一用语：

| 页面用语 | 含义 |
| --- | --- |
| Preview / 查看 | 只切换展示；不表示已审批、不修改使用状态 |
| Save record / 保存记录 | 更新普通产品目录原记录 |
| Save complete draft / 保存整套草稿 | 保存可继续编辑的完整曲线草稿 |
| Publish complete curve version / 发布整套曲线版本 | 固定完整数据版本，供后续选择 |
| Apply as sizing default / 应用为默认 | 选择后续未指定版本的计算所用依据 |
| Stop for new sizing runs / 停止新计算使用 | 曲线停止可用于新计算；保留历史 |
| Switch back / 切回旧版 | 重新选择仍可用的旧版本并显式应用 |

预览附近建议一段说明：**Filters change this view only. Review the conditions you need, save the complete draft, then publish the complete version once. Previewing a condition does not record an approval.**

版本管理区入口统一为 Curve versions — apply, roll back and stop；默认切换及切回在 Apply or roll back the sizing default；停用在 Stop a version for new runs。当前默认的停用按钮不可点击，复用后端已有禁止规则，不新增状态。新草稿的统一发布按钮始终可见，保存完整草稿后才启用。保持保存、发布、默认切换为三个明确动作。

本次不新增逐工况审批清单、审批记录、状态机、自动发布、数据库迁移或默认更换。

### 后续统一管理的目标模型（尚未实施）

建议统一操作语言及数据使用状态，按不同对象保留适用性检查：

| 动作 / 状态 | 目标含义 |
| --- | --- |
| 草稿 | 可编辑、可保存，未进入正式选择来源；需要明确取消草稿及引用保护规则 |
| 发布 / 可供选择 | 将完整参数和所依赖的资料固定成版本；后续编辑生成新版本，不覆盖已发布内容 |
| 应用 / 默认标记 | 单独绑定正式选择来源；默认是绑定关系，不是另一种发布状态，未设默认的可用版本仍可供明确选择 |
| 停止新使用 | 保留版本和历史引用，阻止新计算选用；需先处理当前默认及关联产品 |
| 回退默认 | 将绑定切回此前仍可用、适用性检查通过的旧版；不修改旧计算结果 |

产品链应记录确切版本引用（电芯 → DC 产品；PCS / 变压器参数 → AC 产品；产品 → 附件），避免某条记录原地修改后让旧方案含义变化。发布前验证关联版本及工程适用性；每次计算保存实际采用的参数版本。停止电芯或附件不能只改变显示标记而不处理关联依赖。

落实顺序应为：先确认 Active / Published 的正式业务含义及现有消费者差异，再设计版本快照和引用兼容，最后逐类接入统一页面操作。底层 DC / AC 数值公式仍保持冻结；现行数据选择的任何改变须单独确定范围和验证。普通产品的旧版自动恢复、停止后重启及草稿删除均须先定义规则，再提供按钮。
